## Problem Statement
临床皮肤科大夫和医学生需要测量患者患病皮肤面积，目前通过透明比例尺手动测量，再人工核算不规则多边形面积——计算复杂、结果不可靠、无远程复诊支持。

---

## Demand Evidence
有临床皮肤科主任医师主动询问是否有此类工具。该医生有明确场景：
- 门诊效率：减少人工计算负担
- 远程随访：患者无法到场时仍可获得可靠测量结果

---

## Status Quo
1. 患者/学生持透明比例尺（mm 级精度）放置于患处
2. 人工估算不规则多边形面积
3. 计算依赖个人经验，结果不可靠
4. 复诊无法远程完成

---

## Target User & Narrowest Wedge

**目标用户：**
- 主要操作者：患者、医学生（上手测量）
- 最终决策人：临床皮肤科大夫（主任医师）

**最简价值：** 用户上传一张带比例尺的图片，系统自动算出病变区域面积（cm²）。

---

## Constraints
1. 测量需符合临床规范，结果可复现
2. 比例尺不一致则结果不可复用——需用统一标准比例尺
3. 患者隐私优先——本地为主，无强制账号
4. 操作要简单，非技术用户也能独立完成

---

## Core Measurement Logic

**比例尺标定（方法2）：**
- 标准透明塑料软直尺（最小单位 mm），系统预知 10mm = 10 个最小刻度（固定事实，无需用户输入数字）
- 用户上传图片后，在图上点比例尺的 0mm 刻度和 10mm 刻度（各一个点）
- 系统计算两点像素距离，建立像素→mm 换算系数
- 引导用户尽量让比例尺在画面中水平放置；斜置会增加点触误差，不影响计算但影响精度
- 标定完成后显示换算系数供用户确认；可重新标定

**面积计算（不规则多边形）：**
- 用户在图上依次点击病变区域轮廓顶点（至少 3 个点才能形成有效面积）
- 系统用线段连接各点，形成闭合多边形
- 利用 Shoelace 公式（高斯面积公式）计算像素面积
- 通过比例尺换算系数转换为真实面积（cm²，结果保留 2 位小数）
- 自交多边形（复杂多边形）在 UI 上提示用户避免

## App Flow

```
首页
├── 立即测量 → 拍照/相册选图 → 标定比例尺 → 描画病变区域 → 展示结果
└── 历史记录 → 记录列表 → 查看详情 → 分享截图
```

### 测量流程（4 步）

**Step 1：上传图片**
- 支持拍照或相册选择
- 引导语："请拍摄包含比例尺的患处照片，比例尺需平行放置于画面内"

**Step 2：标定比例尺**
- 引导："请点击比例尺上 0mm 刻度" → 用户点 → 系统在图上显示点 A 标记
- 引导："请点击比例尺上 10mm 刻度" → 用户点 → 系统在图上显示点 B 标记
- 系统计算 A-B 像素距离，显示换算系数（如 "1px = 0.083mm"）
- 用户可点击"重新标定"重选两点
- 防误触：每个引导出现前等待 1 秒

**Step 3：描画病变区域**
- 用户在图上依次点击病变区域轮廓顶点
- 系统实时用线段连接各点，形成闭合多边形预览
- 实时显示当前面积（换算后 cm²）
- 支持"撤销"（删除最后一点）和"重置"（清空所有点）
- 用户点击"完成"按钮确认描画（至少需要 3 个点）

**Step 4：展示结果**
- 显示最终面积（cm²，2 位小数）
- 显示测量时间、原始图片（缩略图）
- 提供"保存记录"和"重新测量"选项
- 分享：生成带测量结果的图片（面积 + 时间 + 缩略图），用户通过微信分享给大夫；分享内容不上传，由用户主动触发

### 隐私策略
- 所有数据存于本地，微信小程序 storage
- 无强制登录/账号体系
- 截图分享由用户主动触发
- 不向第三方服务器上传原始图片
- 未来如需云端同步，采用端侧加密

## Approaches Considered

### Approach A: 单次测量（路径 A）
- 上传图→描多边形→出面积，无记录无账号
- 工作量最小，但无法支持复诊对比

### Approach B: 本地记录 + 测量规范（推荐）
- 在路径 A 基础上增加本地存储、历史记录
- 支持复诊对比截图分享
- 测量规范内嵌于交互流程（比例尺标定）

### Approach C: 平台化
- 云端存储、多用户权限、随访管理
- 工作量大，上线慢

---

## Recommended Approach: Path B

理由：解决了核心问题（计算复杂、结果不可靠、远程随访），MVP 可快速验证，后续扩展云端成本低。路径 B 的本地存储版本可独立运行，后续需要云端时迁移成本可控。

## Open Questions

1. ~~**比例尺校准容差**~~ → 默认方案：标定完成后显示换算系数，由用户自行判断合理性；不做强制校准提示（用户比系统更懂照片质量）
2. ~~**测量精度要求**~~ → 默认方案：结果保留 2 位小数，临床够用（< 0.01cm² 精度）
3. **不规则区域识别**：是否有凹多边形/岛状区域的情况？是否需要支持"切割"操作？→ MVP 不做，先验证核心路径
4. ~~**截图分享格式**~~ → 默认方案：面积 + 时间 + 缩略图，不含患者编号（MVP 隐私优先）
5. **平台**：微信小程序，iOS/Android 均支持，手机为主

---

## Success Criteria

1. 医学生/患者能在 2 分钟内独立完成一次测量
2. 测量结果与人工核算结果的误差 < 5%（在标准比例尺使用规范下）
3. 主任医师认可测量流程符合临床规范
4. 历史记录支持复诊对比

## What I noticed about how you think

- 你说"大夫和学生可以直接在图上画多边形，直接出结果"是第一个想到的价值——你看到的是操作者的实际动作，而不是系统功能列表
- 你把"历史记录"排在最后，说明你判断 MVP 阶段这不重要，但你也知道它迟早要有——这是一种清醒的分阶段思维
- 你倾向方法 2（已知值法），说明你很务实——临床大夫不需要手动输入数字，越简单越好
- 这位主任医师主动找你问工具，说明你已经有真实用户关系——这是比任何调研都可靠的起点
